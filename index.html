King Factory Pipeline

How AI agents run the nightly trading pipeline -- from raw market data to FCM delivery.

What Is This?

Every trading night, King Capital needs to:

  1. Download fresh market data from FRD (First Rate Data)
  2. Generate trading signals from that data
  3. Calculate how much of each commodity to allocate per account (QRT sizing)
  4. Format allocation files for each FCM (broker): StoneX, Wedbush, Marex
  5. Deliver those files via SFTP
  6. Reconcile what was delivered vs. what was actually executed on TT

This is now a Kanban board with AI agents that claim tasks, respect dependencies, and hand off work with structured summaries. Powered by Hermes Agent running on Bilby (CT 271).

How To: Working with the Kanban Board

1. SSH into Bilby

$ ssh root@10.71.20.71

2. View the Board

# List all tasks on the king-factory board $ hermes kanban list --board king-factory ▶ t_12e1cfae ready (unassigned) FRD Data Ingest ◻ t_311d814f todo (unassigned) Signal Generation ◻ t_5fcea100 todo (unassigned) QRT Sizing ◻ t_b32e0ff9 todo (unassigned) CSV Generation ◻ t_4d87bfa6 todo (unassigned) SFTP Delivery ◻ t_bc26f9c3 todo (unassigned) Reconciliation

3. View Task Details

# Show a specific task with its comments and context $ hermes kanban show t_12e1cfae --board king-factory

4. Get Board Stats

$ hermes kanban stats --board king-factory By status: triage 0 todo 5 ready 1 running 0 done 0

5. Create a New Task

# Create a standalone task $ hermes kanban create "Task title" --body "Description" --board king-factory # Create a task that depends on another (won't start until parent is done) $ hermes kanban create "Child task" --parent t_12e1cfae --board king-factory

6. Assign a Task to an Agent Profile

# See available agent profiles $ hermes kanban assignees --board king-factory # Assign a task $ hermes kanban assign t_12e1cfae --assignee ingest-agent --board king-factory

7. Watch Live Progress

# Stream task events in real-time (Ctrl+C to exit) $ hermes kanban watch --board king-factory # Follow a specific task's log $ hermes kanban tail t_12e1cfae --board king-factory

8. Mark Tasks Complete / Blocked

# Complete a task (downstream tasks become ready) $ hermes kanban complete t_12e1cfae --board king-factory # Block a task (with reason) $ hermes kanban block t_311d814f --board king-factory # Unblock $ hermes kanban unblock t_311d814f --board king-factory

9. Add Context / Comments

# Add a comment to a task (agents see this as context) $ hermes kanban comment t_12e1cfae "FRD published at 11:47 PM. Data looks clean."

10. Run the Dispatcher (One Pass)

# The dispatcher reclaims stale tasks, promotes ready tasks, spawns workers $ hermes kanban dispatch --board king-factory
Note: The dispatcher also runs automatically inside the Hermes gateway (hermes gateway start). You only need manual dispatch for testing or intervention.

Key Concepts

🔗

Dependencies

Each task has a parent. Signal Gen won't start until FRD Ingest finishes. The board enforces this -- no human needed. Set via --parent <task_id>.

🤖

Agent Profiles

Each stage can have a specialized agent. Profiles live in ~/.hermes/profiles/ on Bilby. The ingest agent knows FRD's API. The allocator knows TT-to-Bloomberg contract mapping.

💓

Heartbeats

Running agents send heartbeat signals. If an agent goes silent, the dispatcher reclaims the task and reassigns it. No zombie tasks hanging forever.

📋

Structured Handoffs

When an agent completes a task, it writes: what changed, what was verified, what the next agent needs to know. Downstream agents get this context via hermes kanban context <id>.

🔄

Self-Healing

Failed tasks auto-retry (configurable via --max-retries). Persistent failures get blocked and alert. The pipeline doesn't silently die at 2 AM.

👁️

Visibility

Instead of grepping logs, see the whole pipeline on one board. hermes kanban watch streams events live. king-dashboard shows the factory status panel.

Before vs. After

Before (Cron + Bash)

  • Cron fired at 6:30 PM -- 5 hours before FRD published data
  • Prod sync to dead DB (10.71.20.62) killed the pipeline
  • No visibility -- grep logs to find what happened
  • One failure = everything stops, nobody knows
  • No retry logic, no dependency enforcement
  • Midnight date bug broke freshness checks

After (Kanban Agents)

  • Polls at 11:30 PM ET, retries every 5 min until data lands
  • No dead prod sync -- data stays on CT 304
  • Visual board + hermes kanban watch for live status
  • Auto-retry with circuit breaker on persistent failure
  • Dependency chain enforced by the board
  • King Coordinator posts status to #king-dev

Tech Stack

🦅

Hermes Agent

Open-source AI agent framework by NousResearch. Provides the Kanban board, agent profiles, heartbeats, and task orchestration. v0.13.0 on Bilby (CT 271). Kanban docs.

🐙

OpenClaw (Skippy)

AI assistant gateway. Handles communication, memory, monitoring, and cross-channel coordination. Runs on skippy-oc (Mac Mini M4, 10.71.1.21). Docs.

🧠

Open Brain

Knowledge base with BM25 + vector search. Stores HOSTMAP (network topology), SOPs, decisions, and pipeline context. At 10.71.1.15:3100. Every agent checks OB before acting.
